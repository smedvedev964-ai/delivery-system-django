# Система организации доставки заказов «Везём»

Учебный веб-проект на Django. Интерфейс развивается в сторону агрегатора доставки еды: каталог ресторанов, меню заведений, корзина, оформление и отслеживание заказов.

## Стек
- Python 3.11+
- Django 5.2
- PostgreSQL (SQLite используется локально, если `DB_NAME` не задан)
- HTML, CSS, JavaScript, Bootstrap 5

## Запуск локально
1. Создать виртуальное окружение: `python -m venv .venv`
2. Активировать его и установить зависимости: `pip install -r requirements.txt`
3. Настроить `.env` по примеру `.env.example` (если файла-примера нет, локально можно запускать без `DB_NAME` и использовать SQLite).
4. Применить миграции: `python manage.py migrate`
5. Создать администратора: `python manage.py createsuperuser`
6. Заполнить демонстрационные рестораны и меню: `python manage.py seed_restaurants`
7. Запустить сайт: `python manage.py runserver`
8. Открыть `http://127.0.0.1:8000/` и `/admin/`.

## Демонстрационные данные
Команда `seed_restaurants` добавляет демонстрационные карточки известных российских ресторанных сетей и примерные блюда меню. Названия блюд и категории сверяются с меню сетей; цены, рейтинги, количество оценок, остатки и время доставки в проекте демонстрационные. Карточки ресторанов показывают отдельные логотипы, а фотографии блюд загружаются по внешним URL с сайтов сетей и фотобанка Unsplash, поэтому для отображения изображений нужен интернет.

Команду можно запускать повторно: рестораны и карточки блюд обновляются без дублей, а текущие остатки товаров сохраняются.

## Уже заложено
- Кастомная модель пользователя с ролями клиент/курьер/менеджер/администратор.
- Адреса доставки, категории меню, рестораны и блюда.
- Поиск ресторанов, фильтрация по кухне, сортировка и пагинация.
- Страница ресторана с меню, поиском по блюдам и фильтрацией по категориям.
- Модели корзины, заказов, снимки цены/названия/адреса, история статусов и отзывы.
- Профиль курьера и сущность назначения доставки.
- Сервис оформления заказа с серверной проверкой цены/остатка и транзакцией.
- Базовые ORM-агрегаты для аналитики.

## Важные замечания
- Для совместимости с уже существующими записями поле `Product.restaurant` временно допускает пустое значение. Новые демонстрационные блюда привязываются к ресторану.
- Следующий функциональный этап — связать добавление блюд с моделью корзины, запретить смешивание блюд разных ресторанов в одной корзине и завершить оформление заказа.
- Оплата в проекте демонстрационная; эквайринг не подключён.
- Перед реальной эксплуатацией нужны дополнительные тесты, production-настройки безопасности и собственные лицензированные фотографии.
