# Система организации доставки заказов «Везём»

Учебный веб-проект на Django. Интерфейс развивается в сторону агрегатора доставки еды: каталог ресторанов, меню заведений, корзина, оформление и отслеживание заказов.

## Стек
- Python 3.11+
- Django 5.2
- PostgreSQL (SQLite используется локально, если `DB_NAME` не задан)
- HTML, CSS, JavaScript, Bootstrap 5

## Запуск локально
1. Создать виртуальное окружение: `python -m venv .venv`
2. Активировать его и установить зависимости: `pip install -r requirements.txt`
3. Создать локальный `.env` на основе `.env.example`; оставьте `DB_NAME` пустым для SQLite или задайте параметры PostgreSQL.
4. Применить миграции: `python manage.py migrate`
5. Создать администратора: `python manage.py createsuperuser`
6. Заполнить демонстрационные рестораны и меню: `python manage.py seed_restaurants`
7. Запустить сайт: `python manage.py runserver`
8. Открыть `http://127.0.0.1:8000/` и `/admin/`.

## Демонстрационные данные
Команда `seed_restaurants` добавляет демонстрационные карточки ресторанов и блюда меню. Названия блюд и категории сверяются с меню сетей; цены, рейтинги, количество оценок, остатки и время доставки в проекте демонстрационные. Фотографии блюд загружаются по внешним URL, поэтому для отображения изображений нужен интернет.

Команду можно запускать повторно: рестораны и карточки блюд обновляются без дублей, а текущие остатки товаров сохраняются.

## Уже заложено
- Кастомная модель пользователя с ролями клиент/курьер/менеджер/администратор.
- Профиль клиента с одним адресом доставки, регистрацией, входом и поэтапным заполнением данных.
- Каталог ресторанов с поиском, фильтром кухни, сортировкой и пагинацией.
- Меню с поиском, категориями, фильтрами цены и наличия, сортировкой и пагинацией.
- Корзина с изменением количества и очисткой при переходе к другому ресторану.
- Транзакционное оформление заказа со снимками цены и адреса, проверкой остатков и защитой от повтора.
- История заказов клиента и страница заказа с хронологией статусов.
- Отмена до начала сборки с однократным возвратом остатков.
- Кабинет курьера с назначенными доставками и разрешёнными переходами статусов.
- Панель менеджера для обработки заказов и назначения/переназначения курьеров с проверкой лимита.
- Уведомления пользователей и отзыв для собственного доставленного заказа.
- Аналитика по периоду: заказы, выручка, средний чек, популярные блюда и категории, нагрузка курьеров и время доставки.
- История каждого перехода; статусы меняются через бизнес-сервисы, а не прямым редактированием в админке.
- Загружаемые фотографии проверяются по формату и ограничены размером 5 МБ.

## Важные замечания
- Для совместимости с уже существующими записями поле `Product.restaurant` временно допускает пустое значение. Новые демонстрационные блюда привязываются к ресторану.
- Остатки уменьшаются при оформлении и возвращаются при отмене заказа в статусе «ожидает подтверждения» или «подтверждён». После начала сборки отмена недоступна.
- Оплата демонстрационная; эквайринг не подключён. Карты и GPS-трекинг не входят в обязательный объём учебной версии.
- При `DEBUG=False` требуются уникальный `SECRET_KEY`, HTTPS и secure cookies. Используйте собственные лицензированные фотографии.

## Проверки
Проверка конфигурации и миграций:

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
```

Тесты используют изолированную SQLite-базу, чтобы не обращаться к базе из `.env`:

```powershell
python manage.py test --settings=config.test_settings
```

## PostgreSQL
Для проверки целевой базы настройте `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST` и `DB_PORT` в локальном `.env`, убедитесь, что сервер запущен, затем выполните `python manage.py migrate`, `python manage.py check` и `python manage.py test`. Не добавляйте `.env` в Git. Если локальный сервер недоступен, проверка на SQLite не подтверждает работу с PostgreSQL.
