# Система организации доставки заказов

Стартовый каркас курсового проекта по варианту 18. Это веб-сайт на Django, не мобильное приложение.

## Стек
- Python 3.11+
- Django 5.2
- PostgreSQL (основная целевая БД; при отсутствии DB_NAME используется SQLite для локального старта)
- HTML, CSS, JavaScript, Bootstrap 5

## Запуск локально
1. Создать виртуальное окружение: `python -m venv .venv`
2. Активировать его и установить зависимости: `pip install -r requirements.txt`
3. Скопировать `.env.example` в `.env` и настроить PostgreSQL. Если `DB_NAME` не задан, будет использована SQLite.
4. Выполнить: `python manage.py makemigrations accounts catalog cart orders delivery notifications`
5. Выполнить: `python manage.py migrate`
6. Создать администратора: `python manage.py createsuperuser`
7. Запустить: `python manage.py runserver`
8. Открыть `http://127.0.0.1:8000/` и `/admin/`.

## Уже заложено
- Кастомная модель пользователя с ролями клиент/курьер/менеджер/администратор.
- Адреса доставки, категории и товары, корзина.
- Заказы, снимки цены/названия/адреса, история статусов и отзывы.
- Профиль курьера и сущность назначения доставки с поддержкой переназначений.
- Сервис оформления заказа в транзакции с серверной проверкой цены/остатка, резервированием остатков и ключом идемпотентности.
- Сервис ограниченных переходов статусов и серверных проверок ролей.
- Сервис назначения курьера с проверкой доступности и лимита активных доставок.
- Базовые ORM-агрегаты для аналитики.

## Важные проектные решения первой итерации
- Один условный сервис доставки.
- Условная география, без GPS и карт.
- Доставка по умолчанию бесплатна (`delivery_fee=0`); тариф будет вынесен в настройки/конфигурацию.
- Клиент может отменить заказ до подтверждения или на стадии подтверждения.
- Оплата пока демонстрационная и не подключена к эквайрингу.
- Роли сотрудников должны назначаться администратором, а не публичной регистрацией.
